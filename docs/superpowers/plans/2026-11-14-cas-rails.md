# Native CAS Rails Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Implementer seats dispatch no subagents.

**Goal:** Give native CAS an independent panel with its rail below Controls and a reusable ordered rail backend.

**Architecture:** A generic egui strip renders ordered stable-ID entries and edits their independent booleans. App assembly owns bodies and CAS scratch state; existing layout fields remain and native CAS fields default on legacy restore. Compact uses the existing single bottom sheet.

**Tech Stack:** Rust, eframe/egui 0.37, serde/RON, existing integration suite; no new dependencies.

**Spec:** [CAS rails design](../specs/2026-11-14-cas-rails-design.md).

## Global Constraints

- No engine/evaluator, numeric, grammar, Cargo or renderer changes.
- Web has no CAS fields, state, menu entry, tab, sheet variant or module exposure.
- Stored widths remain requested widths, not a cache of automatic squeeze widths.
- Tests live only in `tests/` and new modules register in `tests/suite.rs`.
- Dedicated wasm and browser/manual visual/painted-ink checks are owner-waived, **not passed**.
- [Workflow](../../../references/workflow.md) owns gates/resources, review and preserving merge policy. Owner authorized SDD implementation; controller stops after merge.

## Review Focus

1. Old five-field layout and old bare-style records retain preferences rather than silently defaulting (Task 1 persistence tests).
2. Short windows/long labels/font24 retain reachable, non-overlapping toggles (Task 1 real strip tests).
3. Opening all panels at width701 leaves a usable viewport without overwriting saved widths (Task 1 budget and Task 2 assembly tests).
4. Mode switching, menu actions and close/swipe paths cannot leak Compact selection into wide persistence (Task 2 event tests).
5. Hidden CAS, global reset and stale previews cannot accidentally replace a user's formula (Task 2 CAS event tests).

### Task 1: Ordered rails and backward-compatible layout state

**Interfaces produced** (`src/ui/panel_rails.rs`, public production UI helpers):

```rust
pub struct RailEntry<'a> {
    pub id: &'static str,
    pub label: &'static str,
    pub shortcut: Option<&'static str>,
    pub expanded: &'a mut bool,
}
pub struct RailEntryResponse {
    pub id: &'static str,
    pub response: egui::Response,
    pub label_bounds: egui::Rect,
}
pub struct RailStripResponse {
    pub outer_rect: egui::Rect,
    pub entries: Vec<RailEntryResponse>,
}
pub fn show_rail_strip(
    ui: &mut egui::Ui, id_salt: impl egui::AsIdSalt,
    side: layout::RailSide, entries: &mut [RailEntry<'_>],
) -> RailStripResponse;
pub fn fit_panel_widths(requested: &[f32], budget: f32) -> Vec<f32>;
```

`entries` order controls placement; IDs must be unique and survive reorder.
Returned responses/bounds describe actual widgets, including offscreen entries;
test hit areas intersect each response with its clip rect. Strip uses stable
entry IDs, rail frame/label helpers, selected visuals and **Show/Hide <label>**
tooltips with shortcut suffix only when present. Preserve existing single-rail
helpers for unchanged Presets; avoid changing their public signatures.
`fit_panel_widths` consumes already-sanitized requested widths for expanded
panels only, returns same-order display widths; empty input returns empty,
negative/nonfinite budget acts as zero. Follow the spec's minimum/excess rule.

`LayoutState` adds native fields `cas_expanded: bool`, `cas_width: f32`,
`pub fn toggle_cas(&mut self)` and `DEFAULT_CAS_WIDTH: f32 = 260.0`.
Retain existing five fields/methods; serde default, sanitize and reset as spec.
